# Son64

A PlayStation-era-inspired **boot picker** that lives in the browser. Pick a
generation (Son 1 through Son 5, plus the two portables), and Son64 drops you
into a full-screen HTML recreation of that era's menu style — with animated
backdrops, synthesized sound effects, keyboard/mouse/touch navigation, and a
ROM/disc-image uploader that uses your browser's memory only.

> Son64 is a fan project. **Nothing in this repo is Sony's.** Every visual,
> every sound, every menu label is original, written from scratch to evoke the
> *feel* of each generation rather than copy its assets.

## Open it

- Boot picker: `index.html`
- Each console: `consoles/<id>/index.html`
- Settings: `settings/index.html`

## What's inside

- **Boot picker** — a carousel of seven cards. Keyboard (`←` `→` navigate,
  `Enter` boot, `M` mute), mouse hover and click, and swipe. Each card paints
  its own era-themed canvas so the picker already shows what you're choosing.
- **Capability detection** — CPU cores, device memory (when the browser
  exposes it), WebAssembly, WebGL / WebGL2, renderer name, screen and DPR.
  Each card tells you whether its UI will run smoothly and whether in-browser
  games are even possible for that era.
- **Seven consoles** — each is its own self-contained page:
  - **Son 1** · 1994-era CRT look, memory cards, config, scanlines overlay.
  - **Son 2** · floating wireframe cubes, 4×2 app grid.
  - **Son Portable** · horizontal category list, per-category item strip.
  - **Son 3** · animated wave backdrop, big column-of-columns layout.
  - **Son Vita** · pastel aurora background, two pages of color bubbles.
  - **Son 4** · function rail + large content tiles over a blue sweep.
  - **Son 5** · dark particle sheen, tabs, feature hero, slide-up Control Center.
- **Synthesized audio** — ticks, confirms, backs, startup swell, startup
  chime. All generated by WebAudio; no sampled copyrighted sounds.
- **ROM / disc image upload** — every console has an uploader that reads your
  file into memory only. Nothing is sent anywhere. For most consoles this is a
  shell: actual in-browser emulation of PS3/PS4/PS5 (and PS2/Vita at useful
  speed) **does not exist**. PS1-era is realistically runnable via WASM cores
  that aren't bundled here.
- **Export** — Settings has an "Export a console" row. Click any console and
  it downloads a single `Son64-<id>.html` file with the CSS and the shared JS
  inlined. Open it from anywhere — no server, no other files.

## Keyboard summary

| Key                    | Effect                                 |
|------------------------|----------------------------------------|
| `←` / `→`              | Move selection horizontally            |
| `↑` / `↓`              | Move selection vertically / tabs       |
| `Enter`                | Confirm / boot                         |
| `Esc`                  | Back to the previous view              |
| `M`                    | Mute / unmute                          |
| `C` (Son 5)            | Toggle Control Center                  |

## Honest limitations

- **Sony's actual assets are not here**, by design. The look and feel is
  an original interpretation per era. If you want pixel-perfect XMB, you
  want Sony's firmware, which this project does not reproduce.
- **PS3, PS4, PS5 "play games" is a UI shell.** No one has viable in-browser
  emulation for these. Son64 is clear about this in every uploader.
- **PS2 / Vita emulation** is experimental in native builds; in the browser
  it's at the cutting edge of what WASM can do. The shell accepts the file
  but does not ship a core.
- **PSP-era ISOs** are the most realistically playable of the "post-PS1"
  options via WASM — again, no core is bundled. Add one you trust.
- **Device memory** is only exposed by some browsers. If you don't see it,
  that's the browser, not your machine.

## Hosting on GitHub Pages

The repo is a static site. After pushing, enable Pages:

1. Settings → Pages → Source: *Deploy from a branch*
2. Branch: `main` / root
3. Visit the URL Pages shows.

A GitHub Actions workflow (`.github/workflows/pages.yml`) is included that
deploys Pages on every push to `main`.
